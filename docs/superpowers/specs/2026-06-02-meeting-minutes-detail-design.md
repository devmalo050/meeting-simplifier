# 회의록 상세화 설계

**작성일:** 2026-06-02
**대상:** `commands/stop.md`, `commands/summarize.md` (회의록 생성 프롬프트/템플릿)

## 목표

회의록 본문을 더 상세하고 구조적으로 생성한다. 단, 상세함을 위해 음성에 없는 내용을 지어내지 않는다(환각 방지가 상세함보다 우선).

## 배경 / 현재 형식의 한계

현재 회의록 형식(`stop.md` 4단계)은 요약 · 상세 내용 · 결정 사항 · 액션 아이템 · 발화 내용으로 구성된다. 표준 골격은 갖췄으나:

- **요약**이 한 덩어리라 한눈에 안 들어옴
- **상세 내용**이 "주제별 정리"로만 지시되어 구조가 느슨함(안건 구분·논의 흐름 없음)
- **결정 사항**에 근거가 없고, **액션 아이템**이 평면 불릿(담당·기한 없음)
- 참석자 · 키워드 · 미결 사항 · 다음 단계 같은 항목이 없음

## 비목표 (Non-goals)

- **화자 분리(diarization)** 는 도입하지 않는다. 현재 Whisper는 화자를 구분하지 않으므로 참석자/발화자 자동 추출은 음성에서 이름이 명시적으로 언급된 경우로 한정한다. (무거운 의존성이 필요한 별개 기능)
- 변환·저장 로직(`transcribe_server.py`, `save_meeting.py`)은 변경하지 않는다. 전체 트랜스크립트는 기존대로 `save_meeting.py`가 코드로 첨부한다.

## 새 회의록 구조 (템플릿)

```markdown
# {회의 제목}

**일시:** {날짜 시간}
**녹음 길이:** {N분}
**참석자:** {음성에 이름이 언급된 경우만 — 아니면 줄 생략}
**키워드:** {핵심 주제어 3~6개}

---

## 한 줄 요약
{회의 전체를 한 문장으로}

## 핵심 포인트
- {3~5개 불릿}

## 논의 내용
### {안건 1}
- **논의:** {무엇을 이야기했나}
- **의견/이견:** {다른 관점 — 있을 때만}
- **결론:** {이 안건의 결론 — 있을 때만}
### {안건 2} …

## 결정 사항
- {결정} — *근거:* {왜} ← 근거는 음성에 있을 때만

## 액션 아이템
- [ ] {할 일} — 담당 {이름}/기한 {날짜} ← 담당·기한은 음성에 있을 때만

## 미결 사항      ← 결론 안 난 것이 있을 때만 섹션 등장
## 다음 단계      ← 후속 일정이 있을 때만 섹션 등장
```

(전체 트랜스크립트는 `save_meeting.py`가 본문 끝에 자동 첨부)

## 작성 규칙 (프롬프트에 명시)

1. **음성에 명시된 내용만 작성한다.** 담당·기한·참석자·근거가 음성에 없으면 해당 부분을 비우지 말고 **생략**한다(빈칸·물음표·"미정" 등을 만들지 않는다).
2. **내용이 없는 섹션은 통째로 생략한다.** 단 `한 줄 요약` · `핵심 포인트` · `논의 내용`은 항상 포함한다.
3. **참석자**는 화자 분리가 안 되므로 음성에서 이름이 명시적으로 불린 경우에만 적는다.
4. **추측·추론을 금지한다.** 상세함보다 정확함을 우선한다.
5. **녹음 길이**는 `stop` 경로에서 1단계 `duration_seconds`를 분 단위로 환산해 적는다. `summarize` 경로(기존 파일)는 길이를 모르면 생략한다.

## 영향 범위

- `commands/stop.md` 4단계 회의록 템플릿/지침 교체.
- `commands/summarize.md` — `stop.md`의 3~6단계를 참조하므로 자동 반영되나, "녹음 길이는 모르면 생략" 안내를 추가한다.
- 코드 변경 없음. 버전 범프(plugin.json + marketplace.json)만 동반.

## 검증 방법

- 짧은 입력(예: 2분 단일 화자): 빈 섹션 없이 요약 + 핵심 포인트 + 논의 내용만 나오는지 확인.
- 긴/다주제 입력: 안건별 `###` 소제목과 논의/이견/결론 구조가 나오는지 확인.
- 담당·기한·참석자가 없는 음성: 해당 항목이 "미정" 등으로 채워지지 않고 생략되는지 확인(환각 방지).
